# Райхан Шашлык — платформа управления кафе (с сервером)

Это уже не статичная HTML-страница с `localStorage`, а полноценное клиент-серверное
приложение: Node.js/Express + база данных SQLite + авторизация + живая
синхронизация между устройствами через WebSocket (Socket.IO).

## Что изменилось по сравнению со старой версией

Старый `index.html` был полностью «фейковым» — работал только в браузере одного
человека на одном устройстве:

| Было (только localStorage) | Стало (реальный сервер) |
|---|---|
| Логин/пароль зашиты прямо в JS-коде открытым текстом | Пароли хранятся в БД в виде bcrypt-хэшей, сервер их никогда не отдаёт |
| Данные видны только в одном браузере на одном устройстве | Общая база данных — кассир на телефоне и владелец на ноутбуке видят одни и те же продажи и остатки |
| Любой человек, открыв DevTools, видит логин/пароль в коде страницы | Логин проверяется на сервере, токен доступа (JWT) живёт 12 часов |
| Один общий аккаунт на всё кафе | Несколько сотрудников с ролями: администратор / менеджер / кассир |
| При очистке кэша браузера — вся история продаж пропадает | История хранится в файле базы данных на сервере |
| Изменение цены на одном устройстве не видно на другом, пока не обновишь страницу | Изменения цен и новые продажи мгновенно долетают до всех открытых вкладок и устройств (WebSocket) |
| Нет журнала действий — кто и когда изменил цену или удалил историю | Есть таблица `audit_log` с историей действий |
| Вход не ограничен по числу попыток | Блокировка после 8 неудачных попыток входа в минуту (защита от подбора пароля) |
| Проценты «+12% к вчера» на дашборде были захардкожены и ничего не значили | Проценты считаются от реальных вчерашних продаж |

## Структура проекта

```
raihan-cafe/
├── server.js          # весь backend: API, авторизация, БД, сокеты
├── package.json
├── .env.example        # шаблон настроек — скопировать в .env
├── db/                  # тут появится файл базы данных cafe.sqlite
└── public/
    └── index.html       # фронтенд (тот же дизайн, но данные берёт с сервера)
```

## Запуск локально (проверить, что всё работает)

Нужен установленный [Node.js](https://nodejs.org) версии 18 или новее.

```bash
cd raihan-cafe
npm install
cp .env.example .env
npm start
```

Откройте `http://localhost:3000` в браузере.

При первом запуске сервер сам создаст базу данных и администратора:

```
Логин:  Саидислом
Пароль: 12345678   (или тот, что вы указали в .env как ADMIN_PASSWORD)
```

**Сразу после первого входа зайдите в «Настройки цен» → «Моя учётная запись»
и смените пароль.**

## Как это стало «живой платформой»

- Все данные (цены, продажи, сотрудники) хранятся в файле `db/cafe.sqlite` —
  он не привязан к браузеру и переживает очистку кэша.
- Любое устройство, у которого есть адрес сервера (например,
  `http://192.168.1.50:3000` в локальной Wi-Fi сети кафе, или доменное имя
  после деплоя в интернет), подключается к тем же данным.
- Через Socket.IO сервер сам «толкает» обновления всем открытым вкладкам:
  если кассир на кассе пробивает продажу, дашборд владельца на телефоне
  обновляется без перезагрузки страницы.
- Индикатор в левом нижнем углу сайдбара показывает, подключены ли вы к
  серверу прямо сейчас (зелёная точка — онлайн).

## Как показать это в реальном интернете (не только в локальной сети)

Проще всего — бесплатные/недорогие PaaS-хостинги, которые сами разворачивают
Node.js-проект из архива или Git-репозитория:

1. **Railway.app** или **Render.com** — залейте папку `raihan-cafe` (или
   Git-репозиторий с ней) в новый проект, укажите команду запуска `npm start`
   и переменные окружения из `.env.example`. Сервис выдаст постоянную ссылку
   вида `https://ваш-проект.up.railway.app`.
2. **VPS (Timeweb, Selectel, DigitalOcean и т.п.)** — загрузить папку по SSH,
   `npm install`, затем держать процесс живым через `pm2 start server.js`, и
   поставить Nginx впереди как обратный прокси с бесплатным SSL (Let's Encrypt).

Важно: база данных SQLite — это один файл на диске сервера. Для одного кафе
с несколькими кассами этого более чем достаточно. Если кафе вырастет до сети
из нескольких точек с очень большой нагрузкой, впоследствии можно перейти на
PostgreSQL, поменяв только слой работы с БД в `server.js` — остальной код и
API не изменятся.

## Дальнейшие улучшения, которые стоит рассмотреть

Это не сделано сейчас, чтобы не усложнять первую живую версию, но легко
добавить поверх готового API:

- Резервное копирование `db/cafe.sqlite` по расписанию (просто копия файла).
- HTTPS обязателен, если сервер смотрит в открытый интернет — иначе пароли и
  токены можно перехватить (хостинги вроде Railway/Render дают HTTPS сразу).
- Более тонкие роли: например, кассиру запретить менять цены, а не только
  видеть кнопку.
- Печать чеков/интеграция с фискальным регистратором, если это нужно по
  законодательству Кыргызстана для общепита.
